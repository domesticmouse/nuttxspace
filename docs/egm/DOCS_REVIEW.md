## 2. Architectural Self-Correction & Implementation Across Phases 1–6

Preserving every intermediate snapshot (`concepts_brief.md` -> `v0-draft` -> `pass1` -> `pass2` -> `xiao-rp2350-bargraph/`) provides an auditable record of how EGM surfaced latent hardware, driver, Kconfig, and math defects before C code was written and then compiled clean firmware on the first attempt:

1. **Phase 1 ([`README.md`](README.md) + [`reports/2026-11-16_DRIFT_REPORT.md`](reports/2026-11-16_DRIFT_REPORT.md))**
   - Rolled up the superproject build boundary (`CONFIG_APPS_DIR="../apps"`, `NUTTX_APPS_DIR`, `libapps.a`, and kernel/user-space separation in `INVIOLABLES.md`) across `43` level-1 child contracts without modifying `nuttx/` (`2,607` `README.md` files) or `apps/` (`634` `README.md` files).
   - Running `/egm-drift-report` caught that [`nuttx/README.md`](../../nuttx/README.md#L79) omitted `OSINIT_HARDWARE` from the `g_nx_initstate` progression (`g_nx_initstate = OSINIT_HARDWARE;` in [`nuttx/sched/init/nx_start.c`](../../nuttx/sched/init/nx_start.c#L660)).

2. **Phase 2 ([`designs/concepts_brief.md`](designs/concepts_brief.md))**
   - Six-turn one-concern-at-a-time discovery plus `egm-synthesizer` across 7 Goldfish lenses (`34` unique `README.md` contracts read) surfaced 7 hardware/driver obstacles before specification drafting:
     - Missing `CONFIG_BOARD_LATE_INITIALIZE=y` in upstream `xiao-rp2350:usbnsh`.
     - Hardcoded `pwm_info_s` channel indexing in `rp23xx_pwm.c` (`channels[0]` -> A, `channels[1]` -> B) and shared `/dev/pwm3` slice (`D4` = `PWM3A`, `D5` = `PWM3B`).
     - Dual multi-channel PWM Kconfig guards (`CONFIG_PWM_NCHANNELS=2` vs. `CONFIG_RP23XX_PWM_MULTICHAN` / `CONFIG_RP23XX_PWM_NCHANNELS`).
     - 16-bit duty truncation (`b16ONE` = `65536` wrapping to `0x0000` in `uint16_t`).
     - `PWMIOC_STOP` freezing GPIO output levels unless duty is zeroed and closed.
     - `my_reset()` pin-mux conflict on `GPIO26..29` plus RP2350-E9 digital input buffer (`IE=1`) leakage on `GPIO26`.
     - `<< 19` left shift and continuous `500 kS/s` ADC IRQ behavior in `rp23xx_adc.c`.

4. **Phase 4 Pass 1 ([`reports/pass1/goldfish_review_report.md`](reports/pass1/goldfish_review_report.md) — `10` Goldfish subagents, `104` `README.md` reads)**

Because `RP23XX_ADC_DIV` only paces free-running `START_MANY` conversions, Pass 1 replaced `RP23XX_ADC_DIV` with demand-driven NVIC IRQ gating (`up_disable_irq(RP23XX_ADC_IRQ_FIFO)` / `up_enable_irq(RP23XX_ADC_IRQ_FIFO)`), cutting background IRQs during the 20 ms sleep window to zero (`250 IRQ/s` total).

2. **`up_enable_irq(RP23XX_ADC_IRQ_FIFO)` Ordering Relative to `close(adc_fd)` ([`bargraph_main.c#L389-L390`](xiao-rp2350-bargraph/apps/bargraph/bargraph_main.c#L389-L390), [`#L529-L530`](xiao-rp2350-bargraph/apps/bargraph/bargraph_main.c#L529-L530))**
   - Following Pass 1 `B-1` and [`designs/xiao-rp2350-bargraph.md#L248`](designs/xiao-rp2350-bargraph.md#L248), `bargraphd_daemon()` unmasks `up_enable_irq(RP23XX_ADC_IRQ_FIFO)` immediately before calling `close(adc_fd)` on both startup failure and `bargraph stop` so `interrupt_handler()` in [`rp23xx_adc.c`](../../nuttx/arch/arm/src/rp23xx/rp23xx_adc.c#L176-L196) runs the `g_active_count == 0` peripheral shutdown (`CS=0`, `INTE=0`, `up_disable_irq`, `irq_detach`, FIFO flush).
   - **Safety Analysis**: During daemon sleep/idle, a prior `START_ONCE` conversion has already completed and left `RP23XX_ADC_IRQ_FIFO` pending in the NVIC. Calling `up_enable_irq()` services that pending interrupt immediately and starts the next `2 µs` (`~300` CPU cycles at 150 MHz) conversion, giving `close(adc_fd)` -> `adc_close()` -> `remove_device()` ample time on a single-core thread before the next FIFO interrupt arrives. However, because [`adc_close()`](../../nuttx/drivers/analog/adc.c#L181-L214) only holds `ad_lock` and does not enter a critical section around [`remove_device()`](../../nuttx/arch/arm/src/rp23xx/rp23xx_adc.c#L391-L407) (`g_first_device = NULL` before `g_active_count -= 1`), calling `close(adc_fd)` *first* while `RP23XX_ADC_IRQ_FIFO` is still masked and `up_enable_irq(RP23XX_ADC_IRQ_FIFO)` *second* would eliminate even that tiny 3-instruction window in `remove_device()` while still triggering the `g_active_count == 0` teardown when the pending IRQ is unmasked.

3. **Unassigned Right-Header GPIO Labels (`D10`–`D7`) in [`xiao-rp2350-bargraph/README.md#L53-L56`](xiao-rp2350-bargraph/README.md#L53-L56) & [`BREADBOARD_WIRING.md#L40`](BREADBOARD_WIRING.md#L40) -> Clean in Phase 6**
