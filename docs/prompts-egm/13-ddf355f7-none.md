Subsequent updates with `PWMIOC_SETCHARACTERISTICS` now **also** call `lower->ops->start()`, since `upper->started` is already `true`. According to documentation, `PWMIOC_START` isn't needed on every update. `bargraphd` sets characteristics and starts the PWM, then waits. The critical factor is how the `close()` operation handles the PWM shutdown logic in relation to this sequence. The `pwm_close()` function, when called without a preceding `PWMIOC_STOP`, fails to reset the `upper->started` flag. This flag indicates the PWM device's active state. Consequently, if the application closes the PWM file descriptor without stopping the PWM explicitly, a subsequent start could encounter unexpected behavior because the `started` flag erroneously remains true from the previous run. The required correction involves implementing the explicit stop through `PWMIOC_STOP` before closing the PWM device. The code's fixed-point arithmetic produces an expected steady state where the filtered value isn't equivalent to the raw average, resulting in the filtered value being 4 times the average (`ema_q4 >> 2` = `4 * raw_avg`). This is because the EMA value `ema_q4` is 16 times the raw average (`ema_q4 = raw_avg << 4`). This needs immediate correction to align the filtered output with the intended averaging of the raw samples. The EMA filter, using Q4 fixed-point arithmetic, requires a right shift of 4, not 2, to correctly scale the filtered output. The equation in the documentation is wrong. `ema_q4 >> 2` results in a value four times the expected average. The correct operation should be a right shift of 4 bits to obtain the filtered average, not 2 bits as written. The EMA filter uses the incorrect scaling factor, resulting in a filtered output that's four times the intended average.
